# Admin 会话工作台使用说明

版本：2026-05

适用问题：

- 后台会话列表怎么看？
- 未读数为什么会变化？
- 怎么回复客户？
- 怎么切换人工和机器人？
- 怎么关闭会话？

## 会话列表

Admin 的「会话」页面展示所有未关闭的会话。

每条会话会显示：

- 客户名称或客户 ID
- 外部平台 thread ID
- 渠道名称
- 渠道类型
- Bot / 人工接管状态
- 未读数
- 最近消息时间

渠道类型可能包括：

- Web Chat
- Telegram
- Webhook
- WhatsApp
- WeChat

当前版本主要支持 Web Chat、Telegram 和 Custom Webhook。

## 未读数

当客户发送新消息时，系统会增加会话未读数。

当客服点击会话并加载消息列表后，未读数会清零。

如果未读数没有清零，建议检查：

- 后台是否成功加载消息
- `/api/conversations/:id/messages` 是否返回成功
- 浏览器是否使用了旧版本前端缓存

## 查看消息

点击左侧会话后，中间区域会展示消息时间线。

消息发送者包括：

- customer：客户
- agent：客服人员
- ai：AI 自动回复
- system：系统消息

消息状态包括：

- received：已收到
- sending：发送中
- sent：已发送
- failed：发送失败

## 人工回复

客服可以在会话底部输入内容并发送。

发送后系统会：

1. 写入 `messages`
2. 调用对应渠道 Adapter
3. 如果发送成功，标记为 `sent`
4. 如果发送失败，标记为 `failed` 并记录错误原因

Web Chat 渠道不会调用外部平台 API，访客通过轮询读取客服回复。

Telegram 渠道会调用 Telegram `sendMessage` API。

Custom Webhook 渠道如果配置了 `outbound_url`，会向该 URL 推送回复。

## Bot / 人工接管

会话有两种接管状态：

- bot：允许 AI 自动回复
- agent：由人工客服接管，AI 不自动回复

如果客户问题需要人工处理，客服应切换到人工。

如果问题已解决并希望 AI 继续处理后续问题，可以切换回机器人。

## 关闭会话

客服点击「关闭会话」后，会话状态变为 `resolved`。

关闭后的会话不会作为主要待处理会话展示。

如果客户后续再次发送消息，是否重新打开会话取决于后续业务策略。当前 MVP 主要以已有会话模型为准。

## 客服处理建议

遇到客户问题时建议：

1. 先确认客户来自哪个渠道
2. 查看 AI 引用是否命中正确知识库
3. 如果 AI 回答不完整，人工补充回复
4. 如果涉及配置、Token、Secret，提醒客户不要公开敏感信息
5. 解决后关闭会话
